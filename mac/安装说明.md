## 二、下载与安装

### 下载

从官网下载（推荐）：

```
https://soft.zmm168.top/apps/deepseek-harness
```

安装包为单文件 zip：

| 文件 | 大小 | 说明 |

另有一个**一键安装脚本** `安装泡泡猫DSH.command`（仅 11KB），能把后面的步骤全自动完成 —— 见下方「方式二」。

### 方式一：一键安装脚本（⭐ 最推荐）

把 **`安装泡泡猫DSH.command`** 和安装包（`.zip`）放进**同一个文件夹**，然后双击脚本。

> 如果系统提示「无法打开，因为来自身份不明的开发者」，在脚本上**右键 → 打开**，再点一次「打开」即可（和 app 一样的原因）。

脚本会自动完成：

| 步骤 | 做的事 |
|:---:|------|
| 1 | 检查系统版本（≥ macOS 11）、芯片类型、磁盘空间（≥3GB） |
| 2 | 自动找出同目录的安装包；找不到就弹窗让你选 |
| 3 | 解压到临时目录 |
| 4 | **检查并修复文件权限**（权限丢失会导致双击没反应，很难排查） |
| 5 | 安装到「应用程序」（无权限时自动改用 `~/Applications`）；已装旧版会询问是否替换 |
| 6 | **清除安全隔离标记** —— 这一步能免去之后手动「右键→打开」的麻烦 |
| 7 | 询问是否立即启动 |

装完脚本会自动清理临时文件，不残留垃圾。

**脚本不会碰你的数据** —— 它只替换 `/Applications` 里的 app，`~/Library/Application Support/PaopaocatDSH/` 里的设置、Key 和聊天记录都会保留。

> 没有安装包也能用：脚本会弹出文件选择框让你手动指定。

### 方式二：手动安装

**1) 解压**

双击下载的文件，会得到 **`PaopaocatDSH.app`**。

把它拖进「应用程序」文件夹即可（也可以放在任意位置）。

**2) ⚠️ 首次打开需绕过安全检查（重要）**

本软件**没有购买苹果开发者签名**（一年 99 美元），所以 macOS 会拦一下。这是正常的，不是软件有问题。

**方法一（推荐，最简单）：**

1. 在 `PaopaocatDSH.app` 上**右键**（或按住 Control 点按）
2. 选择 **「打开」**
3. 弹窗里再点一次 **「打开」**

之后再双击就正常了。

**方法二（如果方法一无效）：**

打开「终端」，输入下面这行（把路径换成你的实际位置），回车：

```bash
xattr -dr com.apple.quarantine /Applications/PaopaocatDSH.app
```

> 把 app 拖进终端窗口可以自动填入路径。

**3) 启动**

双击 `PaopaocatDSH.app`，会**弹出一个终端窗口**显示启动进度。

这是刻意设计的 —— 和 Windows 版一样，让你能看到启动过程，出问题时也能看到日志。

看到这一行就说明起来了：

```
正在启动 DSH 服务，请稍等一会（首次启动约需 10~30 秒）...
启动完成后浏览器会自动打开，请不要关闭本窗口。
```

**请不要在浏览器弹出前关闭这个窗口**，否则 DSH 会被一起关掉。

### 方式三：dmg（需要一台 Mac，可选）

`.dmg` 需要用 macOS 自带的 `hdiutil` 制作，无法在 Windows/Linux 上生成。

如果你有 Mac，可以用附带的 `make-dmg.sh`：把它和安装包放同一个文件夹，然后

```bash
bash make-dmg.sh
```

会生成一个带「拖入应用程序」快捷方式的 dmg，并自动验证完整性。

> 注意：dmg **不会**消除安全提示（因为软件未签名）。有没有 dmg，用户首次打开都需要「右键 → 打开」。dmg 的价值主要是看起来更正式、有拖拽引导。

## 四、日常使用

- **启动**：双击 `PaopaocatDSH.app`
- **关闭**：关掉那个终端窗口，或按 `Control + C`
- **如果浏览器没自动打开**：手动访问 `http://127.0.0.1:3080`
- **重复双击**：如果 DSH 已经在运行，再次双击只会帮你打开浏览器，不会启动第二个实例

### 数据位置

所有数据都在这个文件夹里：

```
~/Library/Application Support/PaopaocatDSH/
```

包含聊天记录、设置、API Key。**只在你自己电脑上，不会上传。**

在「访达」里按 `Command + Shift + G`，粘贴上面的路径即可打开。

## 六、常见问题

| 现象 | 解决办法 |
|------|----------|
| **界面一片空白（白屏）** | **用 Safari 会白屏** —— 换成 Chrome / Edge 打开即可；或检查地址是否带了 `?token=` |
| 双击提示「无法打开，因为 Apple 无法检查…」 | 见上面「首次打开需绕过安全检查」 |
| 双击后没反应 | 右键 →「打开」；或检查是否被「隐私与安全性」拦截 |
| 提示文件已损坏 | 终端执行 `xattr -dr com.apple.quarantine /路径/PaopaocatDSH.app` |
| 浏览器没自动打开 | 手动访问 http://127.0.0.1:3080 |
| 提示端口 3080 被占用 | 关掉占用该端口的程序，或重启电脑 |
| 想查看启动日志 | `~/Library/Application Support/PaopaocatDSH/launcher.log` |
| 提示未检测到 git | 终端执行 `xcode-select --install`（仅影响 agent 的 git 操作，不影响基础功能） |
| 想彻底卸载 | 删除 `PaopaocatDSH.app`，再删 `~/Library/Application Support/PaopaocatDSH/` |

## 八、技术说明（给想深入了解的人）

### 为什么同一个包能同时支持两种芯片？

包内同时包含两套 Node.js 运行时和原生模块：

```
Contents/Resources/runtime/node-arm64/   ← Apple Silicon
Contents/Resources/runtime/node-x64/     ← Intel
Contents/Resources/app/node_modules/@koromix/koffi-darwin-arm64/
Contents/Resources/app/node_modules/@koromix/koffi-darwin-x64/
```

启动脚本用 `sysctl -n hw.optional.arm64` 探测硬件芯片（而不是看当前进程，避免 Rosetta 转译时误判），然后选用对应的一套。

### 为什么启动时要加 `--expose-internals`？

DSH 加载插件需要访问 Node.js 的**内部模块加载器**，才能把插件目录当作解析起点。

官方做法是使用一个叫 `node-addon-require-builtin` 的原生库，但该库当前所有已发布版本都要求 **macOS 15.0**，会让 macOS 11~14 的用户直接无法运行。

而 DSH 的加载器代码本身内置了另一条路径：

```js
if (process.execArgv.includes("--expose-internals")) {
    return require(id);          // 走 Node 原生能力，无需那个原生库
}
```

所以启动时带上这个参数，就能绕过 15.0 的限制，把最低系统要求降到 11.0。

> 注意：它检查的是 `process.execArgv`（命令行参数），所以必须写成 `node --expose-internals ...`，用 `NODE_OPTIONS` 环境变量是**无效**的。

### 为什么要内置一个 Python？

**因为 macOS 上 `python3` 不是系统自带的** —— 它由 Xcode 命令行工具提供，而后者有好几个 GB。

Oh Story 的小说创作技能（`story-import` 导入小说、`story-setup` 环境配置）需要调用 Python 来做字数统计、状态提交这类确定性计算。如果不内置，技能去探测 `python3` 时，macOS 会**主动弹窗**要求用户下载安装命令行开发者工具 —— 用户会莫名其妙被要求下载几个 GB 的东西。

所以包里内置了一份**便携版 Python 3.11**（来自 astral-sh/python-build-standalone，各架构约 56MB）：

```
Contents/Resources/runtime/python-arm64/   ← Apple Silicon
Contents/Resources/runtime/python-x64/     ← Intel
```

启动器将它置于 `PATH` **最前面**，因此技能探测 `python3` 时会直接命中内置版本，**永远不会触发系统那个下载弹窗**，用户也无需安装任何东西。

已做的精简：移除了 Tk/Tcl 图形界面、IDLE、ensurepip 等创作技能完全用不到的部分（约 14MB/架构），核心标准库（json、pathlib、re、subprocess 等）完整保留。

> 如果用户自己装过 Python 也没关系 —— 内置版本只是排在前面，不会冲突。

### ⚠️ 请用 Chrome / Edge，不要用 Safari

**这是一个已知的兼容性问题**：DSH 的网页界面在 **Safari 下会一直白屏**（页面什么都不显示）。

原因是 Safari 对 cookie 的 `SameSite=Strict` 策略、以及 ES Module 的 `crossorigin` 检查比 Chrome 严格得多，导致前端拿不到认证凭证。这是 DSH 官方前端的既有行为，不是本安装包的问题。

**解决方案：用 Chrome 或 Edge 打开。**

启动器已经会自动优先选择 Chrome / Edge（依次尝试 Chrome → Edge → Brave → Chromium → Vivaldi），只有在都找不到时才回退到系统默认浏览器。所以正常情况下你不需要操心。

如果**没装 Chrome 系浏览器**，启动时会看到提示，装一个即可（也可以用系统自带的 Safari 之外的任何现代浏览器）。

> 补充：DSH 的访问地址**首次**需要带上 token（形如 `http://127.0.0.1:3080/?token=xxxxx`），
> 启动器会自动用它打开浏览器。**成功访问一次之后**，浏览器就拿到了有效期 30 天的凭证，
> 以后直接访问 `http://127.0.0.1:3080` 即可（建议存成书签）。
>
> 注意 token 每次启动都会变，所以**不要收藏带 token 的地址**，收藏不带 token 的那个。

### 为什么首次打开会有安全提示？

macOS 的 Gatekeeper 会对「从网络下载且未签名」的应用弹窗拦截。软件本身没有恶意行为，但绕过这一步需要用户手动确认，或者购买苹果开发者证书签名（我们暂时没有）。

### 想要 .dmg 格式？

`.dmg` 需要用 macOS 自带的 `hdiutil` 制作，无法在 Linux 上生成。如果你需要，可以在自己的 Mac 上执行：

```bash
hdiutil create -volname "泡泡猫 DSH" -srcfolder PaopaocatDSH.app -ov -format UDZO PaopaocatDSH.dmg
```
