## 3. 每轮改动都要走的三步

```bash
# ① Windows：全部自动（含依赖修复、三元校验、HTTP 冒烟）
bash /root/dshpack-017/win/rebuild.sh          # 约 8 分钟

# ② macOS：重打两个 zip
cd /root/dshpack-017/mac
python3 mkzip.py dist/PaopaocatDSH.app dist/PaopaocatDSH-macOS-v<版本>-universal.zip
#   再用 安装泡泡猫DSH.command + 使用说明.txt + 上面的 zip 组「脚本安装.zip」

# ③ 对**最终交付物**校验（不是构建中间态）
7z x -y -o/tmp/v dist/PaopaocatDSH-Setup-v<版本>-x64.exe
python3 /root/dshpack-017/verify-payload.py /tmp/v
```

`verify-payload.py` 的五项检查（缺一项都不算通过；被跳过的项会明确标注为「未执行」）：

1. **版本一致性**：`profiles/web/node_modules` 里每个 `@deepseek-ai/*` 必须与随包 `app` 同版本；
2. **插件 import**：18 个 bundle 逐个 import；
3. **内置 Mnemon CLI**：启动器 + 目标平台二进制包齐全，且用插件自己的
   `findMnemonCommand`/`mnemonNpmLauncher` 按 win32/darwin 验证可识别；
4. **启动器守卫**：`settings.yaml.imported` 守卫、`MNEMON_CLI_PATH` 注入、依赖提升层守卫；
5. **HTTP 冒烟**：真启动一次，走 token → cookie → 首页，断言 200 且是真实 HTML。

> ⚠️ 第 1 与第 5 项是踩过坑补上的：**只查插件 import 抓不到 UI 级故障**
> （实测旧版 webserver 混入时 import 16/16 全过，首页却 400）。

配套脚本：

| 脚本 | 作用 |
|---|---|
| `win/rebuild.sh` | Windows 全流程：修依赖层 → 清外部符号链接 → 干净目录编译 → 三元校验 |
| `verify-payload.py` | 上面五项校验（可独立对任意 payload 根目录运行） |
| `fix-profile-deps.py` | 清理插件内嵌套的旧 `@deepseek-ai` 副本 + 按插件补齐依赖到提升层 |
| `mac/mkzip.py` | mac zip 打包（保留符号链接；自带死链体检） |

## 5. 本机环境铁律（踩过的坑，别再犯）

### 5.1 NSIS 3.08（deb12）

1. **必须 `LC_ALL=C.UTF-8 makensis`**。默认 `POSIX`/`C` locale 下，脚本里出现任何非 ASCII
   （中文文件名、中文 UI 串）都会**段错误 exit 139**。
2. `SetCompressor /solid lzma` 与 `bzip2` 同样段错误，用默认 `zlib`。
3. **编译目录必须只含 payload**：makensis 处理 `File /r "<目录>"` 时会连带遍历该目录
   **父目录的兄弟目录**。在 `win/` 直接编译会把构建暂存 `tpl/`、`tpl2/` 打进包
   （实测多 806 条目 / +87MB）。`rebuild.sh` 会先 `cp -al` 到 `win-build/` 再编译。
4. payload 内**不能有指向外部的绝对符号链接**（NSIS 会跟随打包，用户机上是死链），
   须先实体化。

### 5.2 macOS 包

1. **符号链接必须用 `ZipInfo` 手工写**（`S_IFLNK` + `ZIP_STORED`，内容=链接目标）；
   `ZipFile.write()` 会把链接存成实体副本，体积暴涨。`mkzip.py` 已实现并自检死链。
2. 版本号有 **3 处**要同步：`launcher/start.command` 的 `VERSION=`、
   `launcher/version.txt`、`Contents/Info.plist`。
3. 便携 Python 双架构、Node 双架构、`--expose-internals` 启动参数都要保留。

### 5.3 shell 操作

- **`pkill -f <模式>` 会自杀**：模式串出现在自身命令行里就会匹配到自己。
  用 `pgrep -f 'app/lib/bin[.]js'`（正则绕开）或**直接用 `$!` 拿后台进程 PID**。
- **`cp -al` 跨文件系统会静默失败**（EXDEV），留下不完整副本 → 误报。
  临时目录必须与被复制对象同文件系统，或回退 `copytree`。
- **硬链接目录里就地改写文件会污染源**：`sed -i` 会断链，但
  `open(p,'w').write(...)` 会写穿到同一 inode。改测试副本时要**先删再写**。
  （这个坑真实发生过：把 payload 的 `cordis.patch.yml` 端口从 3080 改成了随机值。）

## 7. 已修复的真机故障（按时间顺序，都来自用户实机反馈）

### 7.1 插件 `failed to import`（3.1.8 修复）

**根因不是缺依赖，而是「旧文件残留」**：NSIS / robocopy / rsync **只覆盖不删除**，
第一次安装写进安装目录与数据目录的旧版嵌套 `@deepseek-ai`（如 `cosmokit 1.8.3`，
随包 app 是 1.8.5）一直留着，并在解析时**遮蔽**新依赖，导致
`The requested module '@deepseek-ai/cosmokit' does not provide an export named 'createVolatile'`。

**修法**：安装器覆盖安装前 `RMDir /r` 清空 `app/node/git/launcher/data-template`；
两端启动器同步前整层删除 `profiles/web/node_modules` 与 `profiles/node_modules` 再整层拷入。
构建期加了不变量检查（包内出现嵌套 `@deepseek-ai` 直接失败）——该检查还揪出了
`dsh-client-ui-paopaocat` 下同样潜伏的旧副本。

### 7.2 界面打不开，浏览器 HTTP ERROR 400（3.1.9 修复）

**根因**：payload 的 `profiles/web/node_modules/@deepseek-ai/dsh-host-webserver` 是
**0.1.0-rc.8**（7429 字节），随包 app 是 0.1.7-rc.2（13335 字节）。旧 webserver 配新认证层，
每个页面请求都抛异常，被 `dsh-host-webserver` 的兜底处理器变成**空 body 的 400**
（异常只进 `logger.warn`，控制台看不到）。删除旧副本即恢复（首页 200）。

**定位手法**：curl 走完整认证链（`/?token=` → 303+cookie → `/` → 400），
再给该兜底 catch 临时加 `console.error` 打印真实异常。

### 7.3 记忆插件显示「未找到 Mnemon CLI」（3.1.10 修复）

**根因是打包漏项**：开发环境 `profiles/web/cordis.patch.yml` 里显式配了
`cliPath: /dsh/mnemon-cli/node_modules/@mnemon-dev/mnemon/bin/mnemon.js`，
而 payload 既没有这段配置、也没有 CLI 本体。

**修法**：把 `@mnemon-dev/mnemon`（JS 启动器）+ 平台二进制包内置到
`data-template/mnemon-cli/`（Win `mnemon-win32-x64` 14MB；mac 双架构 31MB），
启动器注入 `MNEMON_CLI_PATH`（用环境变量而非写死路径；文件缺失时不设置，可回退用户自装）。

### 7.4 启动期 `atomic-write: timed out waiting for the writer lock`（3.1.11 修复）

**根因是启动器行为**：它每次发现 `settings.yaml` 缺失就从模板重建，而 Mnemon 首次接管后
会把该文件改名为 `settings.yaml.imported`，于是**每启动一次就重演一次「旧设置导入」**；
mnemon 与 `dsh-agency-agents` 抢同一把 `profiles/web/package.json.lock`，
而该锁**默认只等 200ms**，Windows 上必然偶发超时。

**修法**：启动器在 `settings.yaml.imported` 存在时不再重建。数据不丢（仍在 `.imported`，
agency-agents 每次启动会重试）。

### 7.5 macOS 11~14 无法启动（3.1.12 修复）

**根因**：官方 `node-addon-require-builtin` 的 darwin 预编译二进制
`LC_BUILD_VERSION minos = 15.0.0`（本机用 Mach-O 解析确认；arm64 版还带代码签名，
改字节即签名失效）。DSH 0.1.7 的 `dsh-app-boot` 在启动时无条件加载它，
所以旧版 macOS 直接 `host preparation failed`。

**修法**：替换 `app/node_modules/node-addon-require-builtin/lib/index.js`（**仅 mac 包**），
优先走官方原生实现；原生不可用且 `process.execArgv` 含 `--expose-internals` 时，
回退到 `createRequire(__filename)` + `require('internal/…')`
——与 `cordis-plugin-loader` 同机制。原文件备份在
`backups/orig-node-addon-require-builtin-index.js`。
Windows 原生可用，**未改动**。

**验证**：本机 Linux 同样加载不了 darwin 预编译，与旧 macOS 是同一代码路径，
因此可直接启动 mac payload 验证（首页 200 / 396KB）。`verify-payload.py` 对 darwin payload
**故意不安装 linux 预编译**，强制走垫片路径。

## 9. 方法论：这轮踩过的「假通过」

写在最后，因为它比具体 bug 更容易再犯：

1. **只用干净 payload 验证 = 假通过**。前两轮每次都"通过"，而用户机器上躺着旧文件，
   两者根本不是同一状态。正确做法：**注入真实残留**复现故障，再验证修复。
2. **只查插件 import = 假通过**。7.2 那类 UI 故障 import 全过、首页 400。
   必须加版本一致性审计 + 真启动抓首页。
3. **检查被跳过仍算通过 = 假通过**。工具依赖缺失导致 HTTP 冒烟静默跳过，
   脚本却报"全部通过"。已改成：跳过项单列「未执行」，结论必须体现。
4. **把文档结论当已验证事实 = 假通过**。`--expose-internals` 那条是 0.1.5 时代验证的，
   DSH 升到 0.1.7 后失效。**每次 DSH 版本变化，必须重新验证依赖的绕行结论。**
5. **验证工具自身要防污染**。我的校验脚本曾因硬链接就地改写，
   把 payload 端口从 3080 改成随机值；现已加「先删再写」+ 结束时断言 payload 未被改动。
